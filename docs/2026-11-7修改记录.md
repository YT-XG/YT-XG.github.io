**第 79 条设计要点**

- **锁点而非追踪**：圆在生成瞬间记录 `x / y`，之后只走倒计时。3 秒是长预警，若跟随敌人就变成无法躲避的追踪伤害，违背"区域压制"的本意。
- **为什么 210 / 126**：3s 锁点 + 3s CD 的实测命中率只有约 23%~28%（红青双单位约 68%），若单次伤害按长矛冲刺（约 90）或弓箭强化箭（66）取值，期望 DPS 会低到 4~6，角色等于没有输出。210 使期望 DPS 落在 12~18，与现有角色同一量级。
- **边缘减伤 / 溅射**：`coreRatio 0.55` 内全额、外圈 ×0.6，奖励"挤圆心"；`splashMul 0.5` 只作用于同次第 2 个及以后目标，是 2v2 / 3v3 护栏，1v1 不生效（红青两块的 68% 命中率会同时吃到两发，但第二块只有 105）。
- **受护盾影响**：伤害统一走 `hurt()`，因此冰块 / 青金石的护盾会先吸收，与现有伤害规则一致。
- **无羁绊 / 无狂暴**：与弓箭、冰块、草、大狗一致。
- **AI**：`think()` 未改一行；`cast()` 的通用冲刺逻辑因为 `dashTime = 0` 不起作用，`onCast` 只做落点生成，符合"CD 归零直接放"的红线。

**第 80 条设计要点**

- **状态机**：`onCast` 里 `u.cd = 0`，`onTick` 在 `milkT <= 0` 时才 `u.cd = 8`。引导 15s > CD 8s，若在施放瞬间就设 8，会立刻重入引导 → 永久无敌。
- **打断**：`hurt()` 的引导分支**直接 return**，所以引导期间 HP 完全不掉；护盾是**打断计量条**，不是常规减伤。打空 → `interruptMilk()` → CD 从 0 重算**完整 8 秒**（不是进入新的 15s 引导）。
- **99% 而不是 100%**：15 × 6.6% = 99%，保留 1% 残血。理由：引导 15 秒 + 无敌已经足够强，补足 100% 会把「完整引导 = 必杀」写死，失去"必须有人打断 / 打断后还有翻盘"的博弈；99% 仍要补最后一击，且残血目标可能先被击退 / 苟到引导结束。
- **伤害口径**：单位走 `hurt()` → **会吃护盾**、**计入 `dealt / taken`**、能触发死亡与羁绊；敌方种子是召唤物且没有护盾 / 无敌，直接 `s.hp -= maxHp × 6.6%`（不产生伤害归属），血量归零碎裂。决杀 `deathStrike()` 不走 `hurt()`，引导者照样每秒掉 5%。
- **不可移动不是 Steering**：`speedOf` 返回 0 + `collide` 固定桩 + 不改 `ang`；`onCast` 不清方向，引导结束仍沿原方向继续匀速。
- **次数盾 → 护盾**：原始需求是 8 次次数盾。首轮实测（次数盾）除大狗外近乎 100%——因为大狗激光 0.1s/段可在 0.8s 内打满 8 次，而其它角色单次撞击 / 单发箭的频率太低，8 次要 10 秒以上，几乎打不断。按需求方授权改为**血量护盾**后逐档实测：**200 ≈ 95%、120 ≈ 82%、80 ≈ 72.6%、60 ≈ 61%**。最终采用 **80**：平均胜率从 95% 降到 72.6%，并把"能否打断"变成与对手 DPS 挂钩的连续量；60 时弓箭 0%、长矛约 9%（被硬克），过度削弱。
- **反直觉结论**：护盾**越大越强**（护盾保护引导者、打空才打断）。削强应减小 `shieldMax`，不是加大。
- **贴图**：源截图是"卡片式"（顶部标题 / 中部插画 / 底部说明），且是 RGB 无 alpha。最终裁立绘区域 → 连通域 + 洞填充 → 羽化 → 等比缩放，输出透明底 `assets/milk.png`（295×320）；`drawMilk` 用相对路径 `assets/milk.png`，选人界面用同文件的 `img` 字段。**其余 7 个角色仍是 Canvas 占位绘制，本次只接入了野生狗奶的贴图。**
- **AI**：`think()` 未改一行；`canCast` 只拦"引导中"，CD 归零即放，符合红线。

### 83.2 样本量评估（二项分布，95% Wald 区间 = `±1.96·sqrt(p(1-p)/n)`，取最坏 p=0.5）

| 总场次 n | 误差 | 结论 |
|---|---|---|
| 10（最初设想） | **±31.0 个百分点** | 不可用：算出来几乎等于掷硬币 |
| 20 | ±21.9 | 太粗 |
| 24 | ±20.0 | 手机下限（配合矩阵先验） |
| 32 | ±17.3 | — |
| **48** | **±14.1** | 桌面 KO 少场次时的上限 |
| 64 | ±12.3 | — |
| 96 | ±10.0 | 需要 3~8 秒/场，12 场跑不完 |
| 192 | ±7.1 | 不可行 |

**推荐**：不固定局数，按「待算场次」分摊总预算 —— `target = clamp(总预算局数 / 待算场次, 下限, 上限)`。
- 桌面：总预算 **300 局**、单场 16~48 → 12 场小组赛每场 **25 局（±20pp）**，KO 只剩 2~3 场时每场 **48 局（±14pp）**；
- 触屏 / 窄屏：总预算 **96 局**、单场 8~24 → 12 场每场 **8 局**，跑不满 6 局就整场回落矩阵。
- 所有显示值都带**矩阵先验收缩** `(w + 6·p0) / (n + 6)`，避免 4 局全胜就出现 100% / 赔率 1.05。

### 83.3 测速（Node / V8，无渲染，2v2 全单位上场；手机按 3~5× 估）

| 阵容对（2 角色 vs 2 角色） | 1/30 步长 ms/局 | 1/60 步长 ms/局 |
|---|---|---|
| 长矛+冰块 vs 弓箭+草 | 81.0 | 177.9 |
| 狗奶+大狗 vs 铁砧+红青 | 39.9 | 56.1 |
| 铁砧+红青 vs 长矛+草 | 30.8 | 51.1 |
| 弓箭+大狗 vs 狗奶+冰块 | 57.5 | 112.4 |

- 单局平均约 **50ms / 局**（桌面 Node）；手机估 **150~250ms / 局**。
- 1/30 全流程：8 人小组赛 12 场 × 25 局 = 300 局，纯计算 **14.0 秒**（Node 实测）；浏览器按「7ms 计算 / 16.7ms 帧」≈ **30~35 秒墙钟**，期间不阻塞交互。
- 保真度（各 96 局）：`弓箭+大狗 vs 狗奶+冰块` 1/30 = 7.3% vs 1/60 = 8.3%（差 **-1.0pp**）；`长矛+冰块 vs 弓箭+草` 32.3% vs 27.1%（差 **+5.2pp**）。**1/30 可用**。

### 83.4 实现方式

- **不用 Worker**：`file://` 下 Blob Worker 受 CORS 限制，会破坏"双击即开"；改为**主线程 rAF 时间切片**：每帧最多 `ODDS_SLICE_MS = 7ms`，单局可跨帧延续。
- **无渲染**：`render()` 早退、`frame()` 不 tick、`finish()` 在 `simHeadless` 时直接返回；`burst/ring/floater` 临时换成 noop。
- **轮转**：每次取一场跑 1 局（`oddsNextJob` 依次推进 `idx`），所有场次同步涨样本，卡片逐个从「计算中」变「AI n」。
- **换边**：奇数局 `swap=true`（`pick.A/B` 对调），把玩家 a 的胜场折回，抵消固定出生侧偏差。
- **接管与还原**：`oddsSnapshot()` 保存 `units` / 全部特效数组 / `pick` / `ARENA.x,w` / `phase/winner/roundTime/suddenDeath/...` / `paused`；`oddsRestore()` 原样还原。

### 83.5 缓存与失效

- 存储：`localStorage['mcduel.odds.v1'] = { fp, pairs: { '阵容A~阵容B': { n, w } } }`；键按阵容字典序规范化，`flip` 时 `w → n - w`，平局记 0.5。
- 指纹：`fingerprint = FNV1a(JSON.stringify(TYPES) + BALANCE + POOL 摘要 + roundDuration + 'r' + ODDS_RULES)`；**fp 不符整表清空**。
- `ODDS_RULES` 是手动版本号：`JSON.stringify` 抓不到函数体，**改了技能实现必须 +1**。
- `fx.sim` 挂在内存 fixture 上，**不进 `tourSave`**（避免旧样本随存档复活）。
- 实测：同一批 12 场跑完后二次 `oddsCollect` = **0 个 job**（全部命中缓存）。

### 83.6 降级策略

| 条件 | 行为 |
|---|---|
| 计算时间 > 桌面 16s / 触屏 6s | `oddsDegrade()`：>6 局的场次保留部分样本标 `done`；≤6 局标 `off` 回落静态矩阵；置 `tour.oddsOff` 阻止本棋盘反复重跑 |
| 触屏 / 窄屏 | 总预算 96 局、单场 8~24；不够 6 局就整场矩阵 |
| 玩家提前开打 / 返回主菜单 / 重新抽签 / 开关赛事 | 先 `tourOddsStop()`：还原快照、恢复特效、写回缓存 |
| 押注 | 始终可用，用当前最优估计（有样本用平滑值，没有用矩阵） |

### 83.7 与静态矩阵的对比示例（各 48 局，±14pp）

| 对局（2v2） | 静态矩阵（1v1 两两平均） | 后台模拟 1/30 | 1/60（24 局） |
|---|---|---|---|
| 长矛+冰块 vs 弓箭+草 | 40% | **31.3%** | 41.7% |
| 狗奶+大狗 vs 铁砧+红青 | 61% | **29.2%** | 37.5% |
| 铁砧+红青 vs 长矛+草 | 43% | **85.4%** | 83.3% |
| 弓箭+大狗 vs 狗奶+冰块 | 57% | **4.2%** | 12.5% |

差异远超 ±14pp 的有 3 组，说明**静态矩阵（1v1 两两平均）本身就不适合 2v2**：狗奶的引导同时压两个单位、铁砧的落点能覆盖多个目标、冰块/弓箭的短板在 2v2 会被队友放大或掩盖。这正是本功能的主要价值，不只是"跟上版本"。
