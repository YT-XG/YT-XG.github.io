## 3. 每帧绘制顺序

```text
render()
  ├─ ctx.save() + 震屏位移                          index.html:2315-2319
  ├─ drawArena()       场地/网格/中线/边框 + 极寒领域主题  js/40-render.js
  ├─ drawFieldGround() 天气底色 / 局部危险区域 / 随机食物（贴地） js/25-field.js
  ├─ drawDamagePanels() 左右「伤害 / 承伤」排行条        js/40-render.js
  ├─ drawIcePatches()  冰面陷阱（贴地层）             js/40-render.js
  ├─ drawWaters()      水桶狂浪（贴地层，单位之下）    js/40-render.js
  ├─ drawSurfWaves()   大浪淘领域潮汐 / 浪带 / 巨浪（贴地） js/40-render.js
  ├─ drawSeeds()       召唤物 / 草的旧种子（贴地层，当前草不再生成） js/40-render.js
  ├─ drawGrassAuras()  草「生辉」光环（贴地层，单位之下） js/40-render.js
  ├─ drawForgeZones()  铁砧熔铁领域（贴地层）          js/40-render.js
  ├─ drawAnvilMarks()  铁砧落点预警圆（贴地层）        js/40-render.js
  ├─ drawTrail(u) × N  速度尾迹 或 冲刺残影           index.html:2324
  ├─ drawBombs()       炸弹球体与引信                 index.html:2325
  ├─ drawFx()          环 → 粒子 → 飘字（在单位下面）  index.html:2326
  ├─ drawArrows()      箭矢（尾迹/箭杆/箭头）           index.html:2327
  ├─ drawMilkLinks()   野生狗奶引导的全域流失连线（贴地） js/40-render.js
  ├─ 单位按 y 排序后逐个 drawUnit()                   index.html:2329-2330
  ├─ drawAnvilDrops()  下坠中的铁砧（压住单位）        js/40-render.js
  ├─ drawLasers()      大狗终结激光（压在单位之上）    js/40-render.js
  ├─ drawFieldSky()    场地落雷（压在单位之上）        js/25-field.js
  ├─ drawVines()       草的藤蔓（压在最上层）         js/40-render.js
  └─ ctx.restore() → 回写 HUD + 状态栏                index.html:2332-2338
```

| 步骤 | 关键点 |
|---|---|
| 震屏 | `shake` 指数衰减（`index.html:2229-2231`），位移幅度 ×0.6 |
| 排序 | 按 `y` 升序 → 靠下的物体盖住靠上的 |
| 场地环境层级 | `drawFieldGround()` 紧跟 `drawArena()`：先铺天气底色（沙尘 / 雨幕 / 热浪 / 飘雪 / 毒雾 / 血月 / 强风线），再画局部危险区域的半透明圆 + 旋转虚线边界 + 区域名，最后画食物方块（浮动 + 首字标识 + 存活倒计时环 + 名称）；全部压在单位之下 |
| 落雷层级 | `drawFieldSky()` 在单位之后、藤蔓之前：从场地上缘折线劈到落点，外圈淡蓝冲击环；`fieldBolts` 寿命由 `fx()` 推进，对局结束后仍会播完 |
| 食物增益挂件 | `drawUnitStatus()` 读取 `fieldBuffRows(u)`，在单位右侧追加「攻 / 速 / 减 / 冷 / 愈」行；与附魔 / 毒 / 寒冷等旧行共用同一套挂件，最多 8 行 |
| 冰面层级 | 紧跟场地之后、尾迹/单位之前，贴地不遮挡血条 |
| 领域层级 | 极寒领域主题在 `drawArena()` 末尾覆盖绘制，仍在所有贴地残留 / 单位 / 伤害条之下；只读 `st.domainT`，不参与模拟 |
| 狂浪层级 | `drawWaters()` 紧跟冰面之后（两者都是贴地残留），画在种子 / 铁砧预警圆 / 单位之前；水体用径向渐变 + 3 圈错相位扩散波纹 + 旋转浪冠 + 泡沫 + 中心漩涡，`boom` 后只淡出残影（**爆炸后不再有引力与叠层**） |
| 大浪淘层级 | `drawSurfWaves()` 在狂浪之后画全场地潮汐底色、3 道正弦浪带、底部抬起的巨浪与每次拍击的冲击环；`drawSurfSpray()` 在单位之上画浪丝与飞溅水柱；最后一拍叠加全场地白闪 |
| 溺水提示 | 单位血条上方 10px 处画一条 48×4 的**溺水条**（`drownStacks > 0` 才出现，按 `层数/5` 填充）；脚下同时有蓝环 + 上浮气泡，满 5 层加琥珀告警环；状态栏显示「溺水 ×N」；有溺水条时狂暴文字上移 11px 避免叠字 |
| 场地收缩 | `drawArena()` 每帧读 `ARENA`，所以 1v1 中边框/网格**连续**变窄（12 px/s）；2v2 / 3v3 / 赛事 / BOSS 不收缩。视觉上就是墙在慢慢推过来，没有额外收缩特效 |
| 种子层级 | 与冰面同级（贴地），画在单位之下；**草在 2026-11-22 重做后不再生成种子**，这套绘制只服务于遗留召唤物；有种子时仍是独立血条 + 淡虚线治疗光环 |
| 种子受击 | `hurtSeed()` 写 `s.flash = 0.22`，`drawSeeds()` 按剩余时间叠一层白色圆（受击闪白）；每满 1 秒治疗时画绿色扩散环 + 「回春」飘字 |
| 草光环层级 | `drawGrassAuras()` 紧跟种子之后、单位之前：半径 200 的径向渐变 + 两条呼吸虚线圆；`st.auraT` 最后 0.45s 淡出 |
| 藤蔓层级 | 画在所有单位之后，命中时更粗更亮（4px），0.45s 淡出；草的捆绑只借它做视觉，不再定身 |
| 炸弹层级 | 画在单位下方、特效上方，避免遮挡血条 |
| 箭矢层级 | 画在特效之后、单位之前；箭命中即消失，不会长期遮挡 |
| 铁砧层级 | 预警圆贴地（与冰面/种子同级，单位之下）；最后 0.55s 的下坠铁砧画在单位之上，落地瞬间移除并由 `updateAnvilMarks` 按 `tier` 分级补冲击环 / 粒子 / 震屏（普攻 / 砧雨轻震 `min(6,+1.6)`，天陨巨砧 `min(8,+3.5)`，陨铁巨砧 `min(9,+4.5)`） |
| 铁砧预警样式 | 虚线外圈 = 判定边界、细实线内圈 = 全额核心区、外圈扇形 = 剩余时间；最后 0.6s 转红加亮并叠一圈向边界收缩的冲击预兆环；天陨 / 陨铁巨砧固定用熔金 / 赤金警示色（不分阵营），额外画反向旋转符文短划 + 脉动辉光圈 + 旋转亮弧 + 环绕光点；所有档位都有汇聚光流（外圈旋入核心）+ 核心脉动辉光，相位由 `t` 与落点坐标决定（不引随机数） |
| 铁砧下坠样式 | `drawAnvilDrops()` 砧体随落点半径缩放（`m.r/120`），带双层渐淡残影 + 轻微下坠摆动 + 临落地能量池；天陨巨砧冷钢泛金 + 蓝白辉光 + 冷钢彗尾 + 光屑，陨铁巨砧熔金渐变 + 三角火焰尾迹 + 侧翼火舌 + 上飘火星 + 灼热裂纹 |
| 熔铁领域 | `drawForgeZones()` 读 `u.st.forge`（贴地，压在预警圆之下）：熔金光池 + 8 条放射地裂 + 熔岩气泡 + 反向旋转涡流亮弧 + 旋转符文环 / 6 枚符文刻印 + 剩余时间弧 + 7 个带尾迹的上升火星，最后 0.8s 淡出；展开 / 到期收束各补双环 + 火星（`updateAnvilMarks` / `anvilForgeTick`）。**本体阵亡后仍绘制**（已落地的领域由 `updateAnvilForges()` 继续推进）。陨砧引导 / 领域期间 `drawAnvil()` 本体转灼热状态（熔金光晕 + 脉动环）。特效模型接入点见 `js/items/anvil.js` 顶部 A–H 清单，绘制函数为 `drawAnvilMarks()` / `drawAnvilDrops()` / `drawForgeZones()` |
| 铁砧技能冷却环 | 砧雨期间 `u.cd = 0`，冷却环会显示「就绪」；实际由 `canCast()` 在 `volleyN > 0` 时阻止二次施放。若后续要把「施法中」画出来，需要让 UI 读 `u.st.volleyN`，当前未加 |
| 狗奶贴图 | `drawMilk()` 直接 `drawImage(MILK_SPRITE.img)`（`assets/milk.png`，本地资源）；按 `r` 等比适配，`cos(ang) < 0` 时水平翻转；加载失败退化为纯色剪影 |

## 9. 赛事界面（第 64 条新增，第 69 条扩展到竞猜 / 双败）

赛事模式有四块 DOM：

| 元素 | 何时出现 | 内容 |
|---|---|---|
| `#tourBoard`（`.tour-board`） | 非战斗时 | 全屏棋盘：空分组 → 组内对阵卡 → 积分榜 → 双败赛程 |
| `#tourPanel`（`.tour-panel`） | 战斗中 | 左下角比分条（可折叠成小条） |
| `.tb-left` 侧栏 | ≥1240px | 资金 / 本场押注 / 赛事日志 |
| `#banner` | 冠军 | 复用全局横幅 |

`#tourBoard` 内部骨架是 `.tb-wrap > .tb-left + .tb-main`，四个阶段（`tour.stage`）：

1. **setup**：标题 + M 个空组框 + 「开始分配玩家和物品」。
2. **group（第 84 条改版）**：**不再一次铺开全部 vs 对阵卡**。整页只有两块内容：
   - 顶部一张 **「下一场对决」**（吸顶）：A/B 双方名字、两个角色 + A/B 档徽标、当前积分与胜-负、预测百分比、`押A / 开始对决 / 押B`；
   - 下方 M 个组框，每组只列 **组内排名行**：`名次 · 名字 · 两个角色（含 A/B 档） · 胜-负 · 积分`，前两名淡蓝底、下一场双方左侧高亮。
   组内 6 场对阵仍保存在 `tour.fixtures` 里，只是 UI 不再逐场展示；押注只针对「下一场」。详见 §9.3。
3. **group 全部打完** → 自动切成 **2.5 积分榜**：`# 玩家 角色 胜-负 积分 伤害`，前两名高亮，下面只有「生成淘汰赛（双败）」。
4. **ko**：`.tb-lanes` 三条泳道 —— 胜者组、败者组、总决赛 BO5；每轮一列卡片（`待定 / 开打 / 押A / 押B`），每方名字下面再加一行角色 + A/B 档徽标（`.tb-mt-roles`）。
5. **done（结算屏）**：领奖台（冠/亚/季）+ **全部玩家的最终排名表**（`# 玩家 角色 名次 胜-负 积分 伤害`，前三行高亮）+ **最终资金**（初始/结算/净赚亏）；底部「查看赛程 →」可切回泳道图（`tour.finalView`）。

### 9.3 新版小组赛信息页（第 84 条）

| 层级 | 内容 | 实现 |
|---|---|---|
| ① 页头 | 人数 / 组数 / 抽签规则（A 档清单 · B 档清单 · 1A+1B · 蛇形分组） | `renderGroups()` 的 `.tb-head` + `.tb-sub` |

- **押注**：只有下一场可押；工具函数 `tourBetBtn` 的按钮带 `data-bet-key / data-bet-side / data-bet-label`，供局部刷新复用。
- **8 人**：2 组 × 4 人、共 12 场；`narrow` 两列并排（≤560px 单列）。
- **16 人**：4 组 × 4 人、共 24 场；桌面 2×2、手机 2×2、≤560px 单列；下一场按轮次在所有组间交错轮转。
- **选手名单（第 88 → 94 条）**：`TOUR_NAMES` 共 **18 个名字**；`tourOpen()` 用 `tourMakeNames()` 定本届名单——`duelNamesGet()` 里填过的位置用**自定义名**，其余位置从池子里**随机**取且不重名（不再固定包含某两个名字），名单存进 `tour.names` 并随 `tourSave/Load` 持久化，抽签时直接沿用，所以准备页看到的名单就是开赛后的名单；名字只作身份与显示，A/B 档搭配、蛇形分组、赔率、赛程与排名逻辑都不读名字。

### 9.2 赔率后台模拟的状态与降级（第 83 条）

> 逻辑在 `js/70-tour-odds.js`，口径函数在 `js/60-tournament.js`（`tourFxPct` / `tourFxNote`）。

| 项 | 实现 |
|---|---|
| **触发时机** | 每次 `tourRender()` 末尾调用 `tourOddsKick()`；已是 `tour.cur`（观战中）、`tour.oddsOff`（已降级）、或棋盘不可见时直接返回 |
| **后台怎么跑** | 无渲染：`render()` 早退、`frame()` 不 tick、`finish()` 在 `simHeadless` 时算完胜负就返回；主线程 rAF **每帧最多 7ms** 分片，单局可跨帧延续（**不用 Worker**，`file://` 下 Blob Worker 会被 CORS 拦） |
| **进度感知** | 分配/分组/淘汰赛每次渲染后，赔率先显示静态矩阵 + `· 计算中`；每算完一场只改那一场的 `[data-prob]` 文案（`oddsPaint`），**不整块重绘**，所以不会掉帧也不会跳滚动位置 |
| **状态小字** | `· 计算中`（0 局）/ `· 计算中 n`（已出样本但未达标）/ `· AI n`（达标，n = 实际局数）/ `· 矩阵`（降级回落） |
| **押注** | 任何时候都能押；赔率用**当前最优估计**（`tourFxPct`：有样本用平滑后的模拟值，没有就用矩阵）。**押注不再整块重绘**（第 84 条）：`tourPlaceBet()` 只调 `tourSyncBetUi(fx)` 改写资金 / 押注小字 / 押注列表 / 本场按钮，滚动位置与赛程图缩放都不受影响；模拟仍在同一批 `fx.sim` 上继续，不会重跑 |
| **降级** | 计算时间超过预算（桌面 16s / 触屏 6s）→ `oddsDegrade()`：**>6 局的场次保留部分样本并标 `done`**，**≤6 局的场次标 `off` 回落矩阵**，并置 `tour.oddsOff` 阻止本棋盘反复重跑；每场结算后 / 建淘汰赛时清回 `false`，给新对局一次机会 |
| **缓存** | 按「阵容对」存 `localStorage['mcduel.odds.v1']`（`{fp, pairs}`）；`fp` = `TYPES + BALANCE + POOL + 对局时长 + ODDS_RULES` 的哈希，**改数值自动失效**；改技能函数体不会体现在 JSON 里，**必须手动 `ODDS_RULES++`** |
| **手机** | 触屏 / 窄屏（`pointer: coarse` 或宽度 ≤980）自动把总预算降到 6000ms、单场上限降到 24、下限 8；跑不满 6 局就整场回落矩阵，不硬撑 |
| **打断** | `startBattle` / `openMenu` / `tourStartGame` / `tourDeal` / `tourOpen` / `tourClose` 都先调 `tourOddsStop()`：还原快照（`units/pick/ARENA`、`phase/winner/roundTime`…）、恢复特效函数、写回缓存 |

**为什么不是固定 10 局**：p≈50% 时 95% 置信区间 ≈ `±1.96·sqrt(0.25/n)` —— 10 局是 **±31 个百分点**、24 局 ±20、48 局 ±14、96 局 ±10。10 局算出来的赔率几乎等于掷硬币，所以按「待算场次」动态分摊：12 场小组赛每场约 20~25 局，KO 只剩 2~3 场时每场能到 40+ 局。

## 10. 击杀演出（第 65 条新增）

单局分出胜负时不再立刻切回棋盘，而是播 1.9 秒演出：

| 层 | 实现 |
|---|---|
| **放大** | `render()` 开头若 `tourFx` 存在，就 `translate(focus) → scale(zoom) → translate(-focus)`；`zoom` 由 `tourFxTick()` 从 1 缓动到 1.32 再缩回 |
| **时缓** | `frame()` 里演出期间 `fx(sdt * 0.28)`，粒子与飘字变成慢动作 |
| **加分** | `#tourFx` 覆盖层（`.tour-fx.show`）用 `tfx-pop` 关键帧弹「比分 / 胜者 / +N 分」 |
| **时序** | `tourBeginFinishFx()` → 1.9s 后 `tourEndFinishFx()` → `tourOnRoundEnd()` 结算 → 回棋盘 |

镜头焦点取**胜方存活单位的中心**；全灭则退回场地中心。演出里的「比分 / 胜者名」按**玩家**显示（`c.swap` 时把本局红蓝方折回 a / b，第 82 条）。

### 14.3 连线（第 78 / 80 条）

- `bkEdgeD(x1,y1,x2,y2)` 生成折线：横 → 竖 → 横，竖干固定在两列**正中线** `colX=(x1+x2)/2`，端点严格落在**节点边框的中点**（右列节点右边 / 左列节点左边）。
- 两个子节点汇入同一父节点时，上子线只画 `colX` 以上、下子线只画 `colX` 以下，两段竖干在父节点中心**严格上下对称**；因为是两段独立路径，不会出现两条半透明线重叠导致的深色重叠段（旧实现每条边都画整条竖线，汇合处颜色会变深、看着像画歪）。
- 折角用**二次贝塞尔倒圆角**（`r = min(10, |dy|/2, |colX-x1|, |x2-colX|)`，`r<2` 时退回直角），避免缩放后直角端点发毛。
- 同一行（`|dy| < 0.5`）直接画一根横线（败者组单场轮次的直连）。
- 总决赛的两个入口落在决赛框左边缘的 `gfY+22` / `gfY+BH-22` 两点（关于框中心上下对称），胜者组冠军走实线、败者组冠军走虚线，两条线的端点都在节点边框上，不会挤在同一个点上糊成一团。
- 胜者组败者的下落线用 `bkPolyD(pts, 8)`：任意折线逐拐点倒圆角，路径为「框底 → 竖 14px → 横到列间走廊 → 竖到目标框顶上方 → 横到入口 → 竖入框」；多条线的走廊 x 逐条错开 10px、入口 y 错开 8px，避免叠加变深。
- 线宽 / 配色贴合主题：实线 `rgba(120,190,255,.45)`、虚线 `rgba(255,140,110,.55)`（`6 5`）；`.bk-panel{shape-rendering:geometricPrecision}` 减少缩放后的锯齿。

### 14.4 缩放与平移（第 78 条）

`.tb-chart.mob` 是**手势视口**（`overflow:hidden; touch-action:none`），`.tb-bk-m` 是被变换的内容层（`width:max-content` + `transform-origin:0 0`）。不再使用原生滚动，因此**不出现系统滚动条**。

| 手势 | 行为 |
|---|---|
| 手机单指拖动 | 平移（位移 > 8px 才算拖动，拖动后紧跟的 click 被吞掉，不会误选中节点） |
| 手机双指捏合 | 缩放 + 跟随两指中点平移（`bkView` 记录 `s/tx/ty`） |
| 窄窗口鼠标滚轮 | 平移；`Ctrl/⌘ + 滚轮` 以指针位置为锚点缩放 |
| 桌面拖拽 | 改 `.tb-chart` 的 `scrollLeft/scrollTop`（布局与字号完全不动，滚轮仍是原生滚动） |

- 缩放范围：`[max(0.1, min(1, 适配整图的倍率))] ~ 2.6`；初始 `s = 1`（自然尺寸，不为塞进一屏而缩小），`tourOpen()` 时 `bkResetView()`。第 80 条合并后整张双败图变大（8 人 718×666 / 16 人 1206×1230），**初始倍率仍保持 1** 以保证节点字号可读，完整图靠拖动 / 双指缩小查看；实测适配整图的倍率：414×896 视口 8 人 `0.539`、750×340 视口 16 人 `0.120`（仅用于总览）。
- 夹取规则（`bkApply()`）：内容比视口窄/矮时居中，超出时限制在 `[视口 - 内容] ~ 0`，不会拖出空白。
- 状态保存在模块级 `bkView`，`renderBracket()` 末尾调 `bkAfterRender()` 重新绑定并恢复；**点节点选中、押注都不再重建赛程图**（第 84 条），赔率算完等整块重渲染由 `bkAfterRender()` 与 `tourScrollRestore()` 兜底，缩放 / 平移位置不丢。
- 点击选中已改成**局部更新**（`tourSelectKo()`）：只切换 `.bk-mt.sel` 类并重写 `[data-actbar]` 的操作条内容，不重绘 SVG；第一次点方框选中，再点一次开打，与桌面一致（小组赛段不可点）。
