## 3. 遗留 / 待确认

- **桌面端小组赛页面也换成了新版**（下一场 + 组内排名）：桌面外层骨架（左侧资金栏 / 主栏 / `.tb-groups` 两列网格 / 页脚）保持原样，只重排小组赛的信息内容；双败赛程图、积分榜、结算屏均未改动。若需求方要求桌面保留旧的「全部 vs 卡」布局，可只在 `narrow` 时走新版。
- 新版页不再允许跳着打小组赛，只能按「下一场」顺序推进（原先是任意一场都能点「开始」）；如需要保留自由选择，可另加「本组赛程」折叠区。
- 未做真机双指缩放 / 长列表滚动的实测，建议上线前在手机横屏复核一次。
- **3v3 结论**：核心真实支持每方 3 个角色（`pick[team]` 数组长度即槽位数），本轮只是补上主菜单入口，没有改动模拟 / 渲染；接力最多 3 个角色、同时上场最多 3 个角色（红青组合仍是 1 个角色 / 2 个单位）。
- 主菜单的四张入口卡为静态 HTML + `data-size` 绑定；若以后新增人数档位，只需再加一张 `.home-mode[data-size]` 卡并扩展 `setSize()` 的边界检查。
- 选人页手机端只显示**当前编辑方**详情，另一侧隐藏；切换编辑方时详情随之切换，未做真机回归。
- **第 86 条遗留**：本轮只改「显示层」；`tourOnRoundEnd` 里 `winsA/winsB`、`dmgA/dmgB` 的折回逻辑、`tourSettleMatch` 的胜负判定、押注结算与结算屏比分都复核过，未发现换边错记。未做真人观战回归（换边局请重点复核第 2 / 4 局）。
- 比分条在赛事中显示玩家名；普通对局 `teamNames` 为空，仍显示「红方 / 蓝方」。若玩家名以后变长（>4 字），Canvas 伤害条标题（118px 卡片）会偏挤，届时可以缩字号或只显示首字缩写。
- **第 87 条遗留**：高度为按 `BK_*` 常量与 `.tb-bk-sec` 标题 / 内边距的**静态计算**（未在真机量 `offsetHeight`，也未读截图）；手机赛程图在 `.tb-chart.mob` 内是缩放 / 平移层，视口仍占满 `100dvh`，所以“整页收紧”体现在**内容层高度**（`bkMinScale()` 的适配倍率随之变大），底部不会再有第二段图。收起瞬间会重置一次缩放（`bkResetView()`），之后押注 / 整体重绘仍保留缩放位置。
- **第 88 条遗留**：名字池 18 > 16，因此每届**不可能全员到齐** —— 16 人赛缺 2 个名字、8 人赛缺 10 个，跨届轮换（200 届模拟里 18 个名字都出现过）；「兮眠 / 西瓜」每届必到，属于需求指定，其余名字不特殊。每届只在 `tourDeal()` 取一次名，之后（分组、赛程、赔率、存档）都按 `players[i].name` 使用，不再重抽。若以后要固定「同一批人重抽」需另存名单，当前没有「重新抽签」入口。
