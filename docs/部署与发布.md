# 部署与发布（GitHub Pages）

> 本项目是纯静态、零构建的网页，部署就是把 `index.html` + `css/` + `js/` 原样放进仓库。
> 线上地址：**https://yt-xg.github.io/**（仓库 `YT-XG/YT-XG.github.io`）

---

## 1. 线上结构

| 路径 | 内容 |
|---|---|
| `/`（`index.html`） | **游戏本体**（就是本仓库的 `index.html`） |
| `/css/style.css`、`/js/*.js` | 游戏资源 |
| `/wishes.html` | 原来的生日祝福首页（2026-11-6 由 `index.html` 改名而来，内容未改） |
| `/birthday.html`、`/christmas.html` | 原有的两个节日页 |
| `/.nojekyll` | 关闭 Jekyll 处理，避免构建变慢/被过滤 |

> ⚠️ `wishes.html` 里的链接仍然是 `christmas.html` / `birthday.html`，**不要再改名**，否则旧链接失效。

---

## 2. 发布一次改动（标准流程）

```powershell
# 1) 克隆（只需一次；建议放在固定目录，例如 D:\文件\YT-XG.github.io）
git clone https://github.com/YT-XG/YT-XG.github.io

# 2) 把本地改动同步进仓库根目录（index.html / css / js）
#    注意：直接把这三个东西覆盖过去即可，不要动 wishes.html / birthday.html / christmas.html
Copy-Item D:\文件\mc-duel-web\index.html <仓库>\ -Force
Remove-Item <仓库>\css, <仓库>\js -Recurse -Force
Copy-Item D:\文件\mc-duel-web\css <仓库>\ -Recurse
Copy-Item D:\文件\mc-duel-web\js  <仓库>\ -Recurse

# 3) 提交并推送
cd <仓库>
git add -A
git commit -m "feat: 同步最新游戏代码"
git push origin main
```

推送后 **GitHub Pages 会自动重建**（本机实测 5–10 分钟，期间线上仍是旧版本，属于正常现象）。

## 3. 验证发布

```powershell
# 首页标题应为「MC 方块对决 · 组合作战」
(Invoke-WebRequest https://yt-xg.github.io/ -UseBasicParsing).Content -match '方块对决'

# 关键脚本是否已经是新版本（Last-Modified 应为你推送后的时间）
(Invoke-WebRequest https://yt-xg.github.io/js/00-base.js -UseBasicParsing).Headers['Last-Modified']
```

| 现象 | 原因 | 处理 |
|---|---|---|
| 推送成功但线上没变 | Pages 构建有延迟（5–10 分钟） | 等；用 `Last-Modified` 判断是否已更新 |
| 一直不更新 | 上一次构建失败 | 仓库 Settings → Pages → Source 选 `Deploy from a branch` / `main` / `(root)` 后保存，强制重建 |
| 子目录 404 | 文件还没进构建 | 同上；或确认文件确实在 `main` 分支 |
| 手机上打开是竖屏提示 | 设计如此（2.15:1 横向场地，竖屏不提供可玩界面） | 将手机旋转至横屏后游玩 |

## 4. 注意

- **不要删除 `wishes.html` / `birthday.html` / `christmas.html`**：这是需求的硬要求（原页面保留）。
- 仓库里没有 `docs/` 与 `AGENTS.md`（它们只存在于本地项目 `D:\文件\mc-duel-web`），部署时不需要同步。
- 没有 CI、没有 Actions 工作流，构建全部由 GitHub Pages 默认流程完成。
